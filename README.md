# Полиця настілок

Трекер настільних ігор у стилі MyAnimeList: оцінка 1–10, окремі оцінки на
2, 3, 4 і 5+ гравців, журнал партій, теги, нотатка вручну, вибірка за складом
столу, часом і складністю та порівняння до чотирьох ігор поруч.

Правда одна — файл **`ratings.json`** у цьому репозиторії. Кожне збереження
лягає в нього комітом, тож історія оцінок і резервна копія — це одне й те саме.

## Три входи до тієї самої полиці

| Звідки відкрито | Куди пише | Коли зручно |
|---|---|---|
| **GitHub Pages** — https://tavi599.github.io/MyBoardGames/ | просто в репозиторій, через GitHub API | будь-де, з телефона; комп'ютер удома може бути вимкнений |
| **Локальний сервер** — `python "server.py"` | у `ratings.json` на диску, коміт після 90 с тиші | удома, коли зручніше з великого екрана |
| **Подвійний клік по `index.html`** | у пам'ять цього браузера, окремо від усіх | подивитися без мережі; це **не** основна база |

Сторінка сама розуміє, де вона запущена, і показує це плашкою біля кнопок:
`github`, `сервер` або `ця копія`.

### Що робити, якщо зв'язку немає

Нічого. Зміни лягають у чергу в браузері (плашка показує «чекає N») і йдуть
самі, щойно зв'язок з'явиться — при поверненні на вкладку, при появі мережі
або через півхвилини. Злиття завжди за полем `updated`: свіжіший запис
перемагає. Видалені ігри лишаються у файлі мітками `deleted`, інакше стара
копія в телефоні воскресила б викинуту гру.

## Ключ доступу

Щоб писати в репозиторій, сторінці потрібен твій ключ:

1. GitHub → Settings → Developer settings → Personal access tokens →
   **Fine-grained tokens** → Generate new token.
2. Repository access: **тільки** `Tavi599/MyBoardGames`.
3. Permissions → Repository permissions → **Contents: Read and write**.
4. У сторінці: `···` → «Ключ доступу…» → вставити → Зберегти.

Ключ лежить у пам'яті того браузера, куди ти його вставив, і нікуди більше не
йде. Загубив пристрій — відклич ключ на GitHub, і по всьому. Без ключа
сторінка працює в режимі читання.

## Телефон

Відкрий https://tavi599.github.io/MyBoardGames/ у Chrome → меню → «Додати на
головний екран». Далі це звичайний застосунок: відкривається без мережі,
пам'ятає останній стан, накопичені зміни віддає при першій нагоді.

## Файли

Правити треба **`src/`**; `index.html` із них збирається.

```
src/
  head.html         заголовок і шрифти
  styles.css
  markup.html
  tests.js          тести на чисту логіку
  merge-cases.json  випадки злиття, спільні для сторінки й tests.py
  js/
    01-core.js      сталі, статуси, дрібні помічники
    02-storage.js   чотири режими, черга, злиття, GitHub API
    03-filter.js    фільтрування й сортування
    04-list.js      підсумки і список
    05-compare.js
    06-card.js
    07-panel.js     панель керування
    08-menu.js      меню, обмін даними, ключ, BGG
    09-pick.js      «що зіграти?»
```

Назви файлів латиницею, щоб проєкт можна було комусь показати й щоб не
спотикалися інструменти; усе всередині — коментарі, змінні, підписи —
лишається українським.

Файли коду нумеровані, бо склеюються згори вниз і залежать від оголошень
попередніх. Модулів ES тут навмисне немає: сторінка має відкриватися і з
диска подвійним кліком, а туди `import` браузер не пускає.

* `python "build.py"` — збирає `index.html` (його роздає Pages) і
  `tests.html`. Запускати після кожної правки джерел; сервер робить це сам.
* `python "check.py"` — звіряє `ratings.json` зі схемою. **Перед комітом.**
* `python "bgg.py"` — добирає з BGG склад столу, час, вагу, жанри й
  обкладинки для коробок, у яких їх бракує; `--усі` ще й освіжує наявне.
* `python "tests.py"` — перевіряє саму перевірку на підкладених вадах,
  замки сервера й розбір відповіді BGG.
* `tests.html` — тести логіки в браузері (Node у системі немає).

Правило злиття («свіжіший перемагає; при однаковій мітці — той, що
приїхав») має три реалізації: дві в сторінці, одну на сервері. Поділити
між python і браузером код не можна, тож поділено перелік випадків —
`src/merge-cases.json` читають обидві сторони тестів. Правиш злиття —
починай звідти.
* `server.py` — домашній режим. `--пуш` — ще й відправляти коміти.
* `sw.js`, `manifest.webmanifest`, `icon-*.png` — застосунок на телефоні.
  Іконки перемальовує `python "icons.py"`.
* `ratings.json` — дані. Не редагуй руками, поки працює сервер.
* `.github/workflows/bgg.yml` — та сама `bgg.py`, але в репозиторії: щодня
  добирає числа для нових коробок, першого числа місяця освіжує все.

## Числа з BGG

Коробку можна додати звідки завгодно, навіть із телефона в магазині, — а
склад столу, тривалість, «вага», жанри й обкладинка приїдуть самі: раз на
добу дія в репозиторії добирає їх для тих коробок, яким чогось бракує.
Кнопка «Run workflow» у вкладці Actions запускає це негайно. А коли полиця
відкрита з домашнього сервера, у картці є кнопка **«Підтягнути з BGG»** —
та сама робота для однієї коробки, просто зараз. На GitHub Pages її немає,
бо звідти до BGG не дійти: він не пускає до себе браузерну сторінку.

Працює воно **за числовим `bggId`**, і це не примха: пошук за назвою BGG
закрив геть усім — і `xmlapi2/search`, і пошук на самому сайті віддають
403 навіть із браузерним заголовком. Тому єдиний спосіб познайомити нову
коробку з BGG — імпорт вивантаженого звідти CSV (`···` → «Оцінки BGG»):
він проставляє `bggId` за оригінальною назвою, а решту добере дія.

Своїх полів дія не торкається ніколи: `minP`, `maxP`, `minutes`, `weight`,
оцінки, теги, нотатки й власний жанр лишаються твоїми. Обкладинку ставить
лише на порожнє місце. І не піднімає `updated` — інакше її коміт переміг
би правку, що чекає в черзі на телефоні.

## Чого сервер не пускає до себе

Сервер слухає всю мережу — інакше телефон до нього не дістанеться. Це
означає, що постукати може й чужа сторінка, відкрита в тому самому браузері:
прочитати відповідь вона б не змогла, а записати — записала б, і сервер сам
би те закомітив у публічний репозиторій. Тому на кожен запит перевіряються
три речі: `Host` (від «DNS rebinding» — чужий домен, наведений на 127.0.0.1),
`Origin` (чия це сторінка) і `Content-Type` (проста міжсайтова форма
`application/json` не поставить). Своїми вважаються імена без крапки,
числові адреси й домашні суфікси на кшталт `.local`. Помилка 403
`not yours` означає, що спрацював саме цей замок.

Ще два дрібні правила, які легко забути:

* усе, що йде в `href` або `src`, проходить через `посилання()` в
  «01-core.js»: адреси в даних не всі наші (правила вписують руками,
  обкладинки приїжджають із BGG, імпорт JSON приймає взагалі будь-що), а
  «javascript:» у сторінці означає чужий код там, де лежить ключ доступу;
* `bggId` мусить бути числом — він підставляється просто в адресу запиту
  до BGG. І те, і те звіряє `check.py`.

Зламане в репозиторій не поїде: перед комітом сервер сам проганяє
`check.py` і, якщо там помилки, пише про них у консоль і коміт пропускає.
На диск при цьому пише все одно — твоя правка не має зникати через те, що в
файлі знайшлася вада.

## Приватність

Репозиторій **публічний**: оцінки й нотатки бачить будь-хто, і назавжди —
форки й кеші не видаляються. Якщо колись передумаєш, приватний репозиторій
несумісний із безкоштовним Pages: сторінку тоді доведеться хостити на
Cloudflare Pages або в окремому публічному репозиторії.
